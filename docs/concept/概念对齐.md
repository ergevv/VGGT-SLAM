你现在可以把刚才的数据流对应到一套**“术语地图”**了。

先抓住一个关键点：

> **有些概念是在给“数据”命名，例如 Token、Q/K/V、隐藏表示；有些是在给“操作”命名，例如 Softmax、LayerNorm；还有些是在给“一组操作”命名，例如多头注意力、Transformer Block。**
>
> 所以，**不是每遇到一个新名词，网络就多了一步计算。**

下面继续使用刚才的三帧轨迹和固定权重，不重新推导数字，只把概念与步骤对应起来。

## 一、先给完整数据流标上概念名称

仍然是：

```text
第1帧：[1,0]
第2帧：[0,1]
第3帧：[1,1]
```

完整对应关系如下：

```text
原始三帧数据
    │
    │ 每帧作为一个 Token，三帧组成一个 Sequence
    ↓
① 输入投影：2维 → 4维
    Input Projection / Input Embedding
    ↓
② 加上时间位置向量
    Positional Encoding
    ↓
┌────────── 一个 Transformer Encoder Layer / Block ──────────┐
│                                                           │
│  ③ 生成 Q、K、V                                           │
│      Query / Key / Value Projections                      │
│          ↓                                                │
│  ④ Q与K做点积、缩放，必要时加掩码                            │
│      Attention Scores / Scaling / Mask                    │
│          ↓                                                │
│  ⑤ Softmax：打分变成聚合权重                                │
│      Attention Weights                                    │
│          ↓                                                │
│  ⑥ 按权重对V加权求和                                      │
│      Attention Output                                     │
│          ↓                                                │
│  ⑦ 多个头的结果拼接，再做输出投影                            │
│      Concatenation + Output Projection                    │
│          ↓                                                │
│  ⑧ 加回输入，再归一化                                     │
│      Residual Connection + LayerNorm = Add & Norm          │
│          ↓                                                │
│  ⑨ Linear(4→6) → ReLU → Linear(6→4)                      │
│      Feed-Forward Network，简称 FFN，也常称 MLP             │
│          ↓                                                │
│  ⑩ 再次加回输入，再归一化                                  │
│      Residual Connection + LayerNorm                      │
│                                                           │
└───────────────────────────────────────────────────────────┘
    ↓
⑪ 将整个 Block 再执行一遍
    Stacked Layers → TransformerEncoder
    ↓
⑫ 取最后一个位置的特征
    Readout：特征读出
    ↓
⑬ Linear(4→2)，输出下一帧坐标
    Prediction Head / Regression Head
```

其中，**③～⑦合起来是多头自注意力模块；③～⑩合起来才是一个完整的编码器层。** 输入投影、位置编码和预测头，则是这个例子额外组合进去的部分。[PyTorch Docs](https://docs.pytorch.org/tutorials/intermediate/transformer_building_blocks.html)

## 二、输入和中间数据：Token、Embedding、Hidden State 分别是什么？

### 1. Token：网络一次处理的一个序列单元

在我们的例子里，规定：

```text
第1帧 [1,0] → 第1个 Token
第2帧 [0,1] → 第2个 Token
第3帧 [1,1] → 第3个 Token
```

因此这里有 **3 个 Token**，不是 6 个。因为我们选择把“一帧的两个坐标”作为一个整体，而不是把每个坐标单独作为一个序列元素。

你可以把这里的 Token 理解为：

> **注意力矩阵里，一行或者一列所对应的那个序列单位。**

在这套数据组织方式下，第 3 个 Token 关注第 1 个 Token，就是“第三帧的表示读取第一帧的信息”。

### 2. Embedding：把一个 Token 表示成网络使用的向量

对应步骤 **①**：

```text
原始第三帧：
[1,1]

经过输入投影：
[1,1,1,1]
```

这里的四维向量就是这帧的**输入嵌入表示**。

要区分“Embedding 这个概念”和 `nn.Embedding` 这个具体类：我们的连续坐标使用 `nn.Linear(2,4)` 投影；`nn.Embedding` 则通常根据整数索引查表，取出对应的可学习向量。**产生嵌入表示，不一定必须调用 `nn.Embedding`。**[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Linear.html)

### 3. Positional Encoding：位置编码

对应步骤 **②**：

```text
第三帧的内容表示：
[1,1,1,1]

第三个时间位置的编码：
[0,0,0,1]

相加：
[1,1,1,2]
```

在这个例子中，可以这样区分：

```text
输入嵌入：表达“这一帧测到了什么”。
位置编码：提供“这一帧位于哪个时间位置”的线索。
```

这是**加法式位置编码**：内容向量和位置向量维度相同，直接相加。位置编码是 Transformer 中提供序列位置信息的一种机制。[arXiv](https://arxiv.org/html/1706.03762v7)

### 4. Hidden Representation / Hidden State：隐藏表示、隐藏状态

例如，第三帧经过第一层之后：

```text
[1.2607,-1.0768,0.6935,-0.8775]
```

这个向量可以叫：

> **第一层输出的、第三个 Token 的隐藏表示。**

“隐藏”不是说它不可查看，而是说它是**网络内部产生的特征，不是直接测量得到的坐标，也不是最终输出**。

注意：这里没有理由直接把四个通道分别解释成：

```text
位置x、位置y、速度x、速度y
```

我们的模型没有规定这样的物理意义。

把几个概念放在一起，就很清楚了：

| 概念 | 本例中的对应 |
|---|---|
| Token | 一帧轨迹数据这个序列单元 |
| Token 的输入 Embedding | `[1,1,1,1]` |
| 带位置的输入表示 | `[1,1,1,2]` |
| 第一层后的隐藏表示 | `[1.2607,-1.0768,0.6935,-0.8775]` |
| 模型维度 `d_model` | 上述网络内部表示有 4 个特征通道 |

**同一个 Token 的位置身份没有变，但它携带的特征会随着层数不断更新。**

## 三、注意力里的概念：这是最需要分清层级的部分

### 1. Q、K、V：查询、键、值

对应步骤 **③**。

第三帧的输入是：

```text
X3 = [1,1,1,2]
```

三种不同的投影得到：

```text
Q3 = [1,1,1,2]
K3 = [1,1,2,1]
V3 = [2,0,3,-1]
```

它们的职责不同：

| 概念 | 中文 | 在数据流中的职责 |
|---|---|---|
| Query，Q | 查询 | 当前 Token 用它去匹配其他位置 |
| Key，K | 键 | 每个位置提供一个供 Query 匹配的向量 |
| Value，V | 值 | 匹配完成后，真正被加权汇总的内容 |

**Q/K 决定怎么分配权重；V 决定按照权重汇总什么。** 注意力输出就是由 Query 与 Key 的匹配结果，对 Value 进行加权汇总。[arXiv](https://arxiv.org/html/1706.03762v7)

还有一个特别重要的区别：

```text
WQ、WK、WV：网络的可学习参数。

Q、K、V：当前输入经过参数变换之后，产生的中间数据。
```

不要把 Q、K、V 本身理解成固定存储在网络里的权重矩阵。

### 2. Attention Scores、Attention Weights、Attention Output：三者不是一回事

它们分别对应步骤 **④、⑤、⑥**。

继续看第三帧、第一个注意力头：

| 名称 | 刚才的具体数值 | 表达的含义 |
|---|---|---|
| **Attention Scores：注意力打分** | `[0.7071,0.7071,1.4142]` | 当前 Query 与三个 Key 的缩放点积 |
| **Attention Weights：注意力权重** | `[0.2483,0.2483,0.5035]` | 对三个位置分别使用多少聚合权重 |
| **Attention Output：注意力输出** | `[1.5035,0]` | 按上述权重汇总 Value 后得到的新特征 |

所以这段数据流是：

```text
三个匹配打分
    ↓ Softmax
三个聚合权重
    ↓ 对三个Value加权求和
一个新的二维特征向量
```

数学对应是：

\[
S=\frac{QK^\top}{\sqrt{d_{\text{head}}}},
\qquad
A=\operatorname{softmax}(S+M),
\qquad
O=AV
\]

其中 \(M\) 是可选的加性掩码。这里暂不考虑 Dropout。[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.scaled_dot_product_attention.html)

**注意力权重不是最终特征，也不是“这帧测量正确的概率”。** 在本例里，它只是决定 Value 如何被加权相加。

### 3. 缩放点积注意力：是在给“计算方法”命名

**Scaled Dot-Product Attention** 对应：

```text
Q与K做点积
    ↓
除以 √d_head
    ↓
Softmax
    ↓
对V加权求和
```

名称中的每个词都对应一个操作：

```text
Dot-Product：用点积计算匹配打分。

Scaled：把打分除以 √d_head。

Attention：根据匹配结果，对Value加权汇总。
```

也就是你已经看懂的：

\[
\operatorname{Attention}(Q,K,V)
=
\operatorname{softmax}
\left(\frac{QK^\top}{\sqrt{d_{\text{head}}}}\right)V
\]

这不是在前面的注意力之后，再额外执行的一种注意力。**它就是前面那套计算的完整名称。**[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.scaled_dot_product_attention.html)

### 4. 自注意力：是在给“Q/K/V 的来源”命名

**Self-Attention** 指：

```text
Q来自当前这三帧；
K来自当前这三帧；
V也来自当前这三帧。
```

即同一段序列内部进行信息交互。[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.MultiheadAttention.html)

“自”指的是**同一份序列关注自身的各个位置**，不是每一帧只能看自己。

所以：

```text
第三帧读取第一帧、第二帧、第三帧的信息
```

仍然叫自注意力，而不是只有：

```text
第三帧读取第三帧
```

才叫自注意力。

### 5. 多头注意力：是在给“并行组织方式”命名

**Multi-Head Attention，MHA** 对应步骤 **③～⑦整体**。

本例同一个第三帧，通过两个头得到：

```text
头1：
[1.5035,0]

头2：
[2.4359,-0.4359]
```

然后：

```text
拼接：
[1.5035,0,2.4359,-0.4359]

再经过输出投影：
[3.9394,0,2.4359,-0.4359]
```

“多头”表示有多组投影和注意力计算，再把结果组合起来。这里 `d_model=4、nhead=2`，所以每个头的投影维度是 2。[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.MultiheadAttention.html)

特别注意，两个名称里都有 `Head`，但含义不同：

```text
Attention Head：
注意力模块内部的一个计算分支。

Prediction Head：
网络末尾把隐藏特征映射成任务输出的模块。
```

前者在步骤 **③～⑦**，后者在步骤 **⑬**。

### 6. 把几个“注意力”名称放在一张表里

| 名称 | 它在回答什么问题？ | 本例中的答案 |
|---|---|---|
| **自注意力** | Q/K/V 从哪里来？ | 来自同一段三帧序列 |
| **缩放点积注意力** | 单个头怎样计算？ | 点积、缩放、Softmax、加权汇总 |
| **多头注意力** | 有多少组并行计算，如何合并？ | 两个头，拼接后做输出投影 |
| **因果注意力** | 一个位置允许读取哪些位置？ | 仅允许当前位置及之前的位置 |

因此，同一个模块可以同时叫：

> **使用缩放点积计算的、多头、因果自注意力。**

这些限定词描述的是不同方面，而不是四个前后串联的模块。[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.scaled_dot_product_attention.html)

## 四、Mask：它不是一种新特征，而是在规定信息流向

### 1. Causal Mask：因果掩码

对应步骤 **④**，作用在 Softmax 之前。

例如，第二帧原来的打分：

```text
[0.0000,0.7071,0.7071]
```

禁止读取第三帧后：

```text
[0.0000,0.7071,-∞]
```

Softmax 后变成：

```text
[0.3302,0.6698,0]
```

因此：

```text
来自第三帧的Value，权重变成0。
```

这就是 **Causal / 因果** 在这里的具体含义：不允许当前位置通过注意力直接读取未来位置。[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.scaled_dot_product_attention.html)

### 2. Padding Mask：补齐掩码

假设一条序列被补成：

```text
第1帧、第2帧、PAD
```

Padding Mask 的意思是：

> **最后一个位置不是真实观测，不要把它当作可读取的信息来源。**

两种掩码的区别：

```text
因果掩码：
这个位置存在，但对于当前预测来说，它属于未来。

补齐掩码：
这个位置只是为了组成整齐的batch而补出来的。
```

在 PyTorch 的这两个编码器模块中，布尔掩码的 `True` 表示屏蔽。Padding 掩码也不保证被补齐位置的最终输出自动为零，做池化或计算损失时仍需排除无效位置。[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.MultiheadAttention.html)

**位置编码告诉模型“这是哪个位置”；掩码规定模型“能读取哪些位置”。两者不能相互替代。**

## 五、注意力后面的概念：Residual、LayerNorm、FFN、Dropout

### 1. Residual Connection / Skip Connection：残差连接、跳跃连接

对应步骤 **⑧、⑩中的加法**。

刚才第一次残差是：

```text
本层原始输入：
[1,1,1,2]

注意力计算结果：
[3.9394,0,2.4359,-0.4359]

两者相加：
[4.9394,1,3.4359,1.5641]
```

概念对应：

\[
y=x+f(x)
\]

它给原来的表示提供一条直接参与输出的通路，让分支计算可以作为对原表示的更新。编码器的注意力子层和前馈子层外面，各有一次这样的残差连接。[GitHub](https://github.com/pytorch/pytorch/blob/v2.14.0/torch/nn/modules/transformer.py)

这里的“残差”，不是预测坐标与真实坐标之间的误差，也不是 SLAM 中的重投影残差；只是这个网络连接结构的名称。

### 2. LayerNorm：层归一化

对应步骤 **⑧、⑩中的归一化**。

例如：

```text
之前：
[4.9394,1,3.4359,1.5641]

之后：
[1.4133,-1.1122,0.4495,-0.7506]
```

这里 `LayerNorm(4)` 对**同一个 Token 的四个特征**计算均值、方差并归一化，随后还可以进行可学习的缩放和平移。它不是对三帧做时间平均，也不是对整个 batch 一起归一化。[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.LayerNorm.html)

### 3. Add & Norm：不是第三种操作，而是前两者的合称

论文结构图里的：

```text
Add & Norm
```

在刚才的例子里就是：

```text
Add：残差相加。
Norm：LayerNorm。
```

进一步会遇到两个词：

| 概念 | 主要顺序 | PyTorch 配置 |
|---|---|---|
| **Post-LN：后归一化** | 子层计算 → 残差相加 → LayerNorm | `norm_first=False` |
| **Pre-LN：前归一化** | LayerNorm → 子层计算 → 残差相加 | `norm_first=True` |

你刚才跟踪的数字采用的是 **Post-LN**。[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.TransformerEncoderLayer.html)

### 4. FFN / MLP：前馈网络、多层感知机

对应步骤 **⑨整个子模块**：

```text
Linear(4→6)
    ↓
ReLU
    ↓
Linear(6→4)
```

你刚才看到的：

```text
四个特征
    ↓
六个特征组合
    ↓
将负数置零
    ↓
重新组合成四个特征
```

整体就叫 **Feed-Forward Network，FFN**。这类由线性层和非线性激活组成的模块，也常被称为 **MLP**。

原始 Transformer 中更完整的名称是：

> **Position-wise Feed-Forward Network：逐位置前馈网络。**

“逐位置”强调：同一层中的每个 Token，都分别通过相同参数的前馈网络；这个子模块本身不直接混合不同 Token。[arXiv](https://arxiv.org/html/1706.03762v7)

因此，一个非常有用的理解是：

```text
Attention：
不同Token之间交换信息。

FFN：
在每个Token内部，对已有特征进行非线性加工。
```

其中 `ReLU` 是 **Activation Function，激活函数**。它属于 FFN 内部的一步，不是整个 FFN 的另一个名字。

### 5. Dropout：随机丢弃，用于正则化

Dropout 会在训练时随机把部分中间元素置零，并对保留元素进行缩放；在 `nn.Dropout` 的评估模式下不进行这种随机丢弃。[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Dropout.html)

它可以出现在注意力权重、子层输出和 FFN 中间等位置。刚才设置：

```python
dropout=0.0
```

因此它在数值流里相当于没有改变数据。[GitHub](https://github.com/pytorch/pytorch/blob/v2.14.0/torch/nn/modules/transformer.py)

**Dropout 不等于 Padding Mask：前者是训练中的随机正则化，后者是在标记无效序列位置。**

## 六、模块层级：Attention、Block、Encoder、Prediction Head

这是把所有概念组织起来的关键。

### 1. 一个 Attention 不是一个完整 Transformer 层

刚才的层级关系是：

```text
TransformerEncoder
    │
    ├── 第1个 TransformerEncoderLayer / Block
    │      ├── 多头自注意力
    │      ├── 残差连接与LayerNorm
    │      ├── FFN
    │      └── 残差连接与LayerNorm
    │
    └── 第2个 TransformerEncoderLayer / Block
           ├── 多头自注意力
           ├── 残差连接与LayerNorm
           ├── FFN
           └── 残差连接与LayerNorm
```

所以：

> **Attention 是 Block 内部的子模块；Block 是 Encoder 堆叠的单位。**[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.TransformerEncoderLayer.html)

### 2. “宽度、头数、深度”分别对应什么？

| 概念 | 本例配置 | 含义 |
|---|---|---|
| 模型宽度 | `d_model=4` | 每个 Token 在层与层之间携带四维表示 |
| 注意力头数 | `nhead=2` | 每层内部有两个注意力头 |
| 每头维度 | `4/2=2` | 每个头使用二维投影特征 |
| FFN 中间宽度 | `dim_feedforward=6` | FFN 临时把四维扩展为六维 |
| 网络深度 | `num_layers=2` | 前后串联两个完整 Block |

**两个头是并行分支，两个层是串行深度。** 不要把二者理解成同一个参数。[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.TransformerEncoderLayer.html)

### 3. Readout 与 Prediction Head：从特征得到任务结果

对应步骤 **⑫、⑬**。

先做读出：

```python
last_feature = encoder_output[:, -1, :]
```

这是选择最后一个位置的特征，本例中得到：

```text
[1.6084,-0.4165,-1.1104,-0.0815]
```

再通过预测头：

```python
prediction = head(last_feature)
```

得到：

```text
[1.0532,-0.4572]
```

所以：

```text
Readout：
决定用哪些隐藏特征去完成任务。

Prediction Head：
把选出的隐藏特征变成任务输出。
```

这里预测的是连续坐标，因此也可以叫 **Regression Head：回归头**。

**前面的 Attention 输出投影和这里的 Prediction Head，虽然都可能使用 Linear，但不是同一个模块：前者融合多个头的内部特征，后者产生最终任务结果。**

## 七、两个经常听到、但刚才例子里没有的概念

### 1. Cross-Attention：交叉注意力

它和 Self-Attention 的主要区别是来源：

```text
Self-Attention：
Q、K、V来自同一份序列表示。

Cross-Attention：
Q来自一份表示；
K、V来自另一份表示。
```

例如，可以设计“未来位置查询向量”去读取“三帧历史轨迹特征”：

```text
未来查询 → Q
历史轨迹 → K、V
```

在经典 Encoder–Decoder Transformer 中，解码器使用自己的表示产生 Query，读取编码器输出产生的 Key 和 Value。[arXiv](https://arxiv.org/html/1706.03762v7)

**刚才的网络只有历史序列内部的自注意力，没有单独的交叉注意力模块。**

### 2. Transformer Decoder：Transformer 解码器

刚才最后那个：

```python
nn.Linear(4, 2)
```

只是预测头，**不是 `nn.TransformerDecoder`**。

PyTorch 的 `TransformerDecoderLayer` 包含自注意力、读取编码器输出的多头注意力，以及前馈网络，并接收 `tgt` 和 `memory` 两份主要输入。[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.TransformerDecoderLayer.html)

因此，刚才完整模型的准确描述是：

> **输入投影和位置编码 + Transformer Encoder + 回归预测头。**

而不是“Encoder 后面接了一个 Transformer Decoder”。

## 八、最后分清：参数、中间数据、超参数

这三个概念贯穿整个网络，而不是对应某一个独立步骤。

| 类别 | 本例中是什么？ | 如何变化？ |
|---|---|---|
| **Parameter：可学习参数** | 输入投影权重、Q/K/V 投影权重、FFN 权重、LayerNorm 的缩放与偏置、预测头权重 | 训练时由优化过程更新 |
| **Intermediate Tensor / Activation：中间张量、激活值** | Q/K/V、注意力权重 `[0.2483,0.2483,0.5035]`、各层隐藏表示 | 每次前向计算根据输入和参数重新产生 |
| **Hyperparameter：超参数** | `d_model=4`、`nhead=2`、`num_layers=2`、`dim_feedforward=6` | 由模型设计或配置指定，不是这次反向传播直接更新的权重 |

可学习参数由各模块保存；前向计算产生中间结果，反向传播再沿计算关系求出损失对参数的梯度。[PyTorch Docs](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Linear.html)

所以，你刚才完整看懂的那条数值通路，整体叫：

> **Forward Pass：前向传播。**

拿最终预测与真实下一帧比较，得到的是：

> **Loss：损失。**

从损失反向计算各个参数应如何调整所需的梯度，叫：

> **Backpropagation：反向传播。**[PyTorch Docs](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html)

---

**把这套概念压缩成一句话：**

> **Token 是序列里的单位，Embedding 是它的输入表示，位置编码提供位置线索；Attention 让不同 Token 交换信息，FFN 加工每个 Token 内部的特征，残差与归一化组织每次更新；这些组成一个 Block，多个 Block 组成 Encoder，最后由读出操作和预测头把隐藏表示变成任务结果。**
